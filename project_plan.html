用不对称过程监督提升小模型数学推理

Asymmetric Process Reward Adaptation for Small-Model Mathematical Reasoning
3 人 · 1–2 张 RTX 5090 · GSM8K / MATH · 正常 CoT · GRPO + LoRA

固定研究问题：在在线更新过程评分器时，能否利用“答错意味着解答至少有一处错误”，同时避免把“答对”错误地当成“每一步都对”，从而提高后续 RL 训练的数学准确率？
唯一核心改动：在线评分器更新采用不对称监督：新生成的错误解答提供整条错误信号；新生成的正确解答不自动提供全程正确信号。保留少量公开、已有步骤标签作为锚点。

这是一项有具体增量的研究计划。在线奖励更新、弱监督步骤评分和 GRPO 都有已有方法；我们的可检验贡献限定为：在相同 RL 系统中，改变在线过程评分器对正确／错误结局的监督规则。不主张首创在线 PRM，也不预设准确率一定提升。文献检索未找到与这一完整更新规则完全相同的实现，但这不等于穷尽性的首次性证明。

1. 为什么问题真实存在

最终答案正确，可能来自正确推导，也可能来自中途自我纠正、错误抵消或碰巧命中。如果把这些解答整体当作“没有错误”的训练样本，过程评分器可能学会认可其中的错误步骤。

本次直接核算了 ProcessBench 官方数据的 3bdcd53 版本。条件为 final_answer_correct == true 且 label != -1，其中 label 表示首个被标注的过程错误位置：

公开评测子集最终答案正确的解答其中仍有过程错误条件比例
MATH5009418.8%
GSM8K20073.5%

这是已有评测集的描述性统计，不是我们模型的测量，也不是自然训练分布中的发生率。该集合的抽样构成不能用来估计未来 RL 的噪声率。原始文件、哈希、样本 ID 和可复算脚本放在 evidence/。我们只用这一统计说明问题确实存在；不使用 ProcessBench 调训练超参数。

真实例子：ProcessBench 的 math-509，生成模型为 Qwen2.5-1.5B-Instruct。它算 tan(315°)，中间把第四象限写成“sin 为正、cos 为负”，最后却答对 −1。数据将第 3 步标为错误。这说明正确结局不能给每一个中间数学判断背书。

2. 方法怎么运转

① 学生做题
1.5B 策略模型每题生成 8 条正常解答。
② 分开评分
规则验证最终答案；1.5B PRM 给步骤分。
③ GRPO 更新学生
使用结果奖励与过程分组合，更新策略 LoRA。
④ 更新评分器
复用刚才的错误解答，加上固定公开步骤锚点；下一轮使用新版 PRM。

两个模型角色不同：策略模型负责解题；PRM 负责提供学习信号。GRPO 使用奖励更新策略。整个实验最终评估策略模型自己生成一次答案的正确率，测试时不需要 PRM，也不使用选优投票。

  1. 从同一初始策略与同一预训练 PRM 开始。策略和 PRM 都只微调 LoRA；不增加模型 head。
  2. 每一训练轮内冻结 PRM 版本，完成一段正常 on-policy GRPO。所有方法使用相同题目顺序、采样设置和预算。
  3. 保存有完整结尾、答案可可靠解析的解答。对答案明确错误的解答，给 PRM 的信息只是“整条解答中至少存在一个错误”，不伪造具体错误位置。
  4. 对新生成且答案正确的解答，不创建“全程无错”的 PRM 标签。这些解答仍正常进入策略的 GRPO 更新，并获得正确答案奖励。
  5. 混入同一份现成 PRM800K 步骤标签，帮助 PRM 保持对正确步骤与错误步骤的识别能力。它们不是团队新标注的数据，且所有可训练 PRM 对照使用完全相同的锚点。
  6. 在轮与轮之间更新 PRM，随后恢复策略训练。旧解答只用于评分器监督学习，不用于 off-policy 更新策略。

“至少一处错误”仍然不能唯一定位错误位置。方法依赖预训练 PRM 与公开步骤锚点，不承诺仅凭终答标签识别任意推导错误。失败样本不会被整体标成“每一步都错”。截断或解析不确定的输出不进入 PRM 的弱监督更新。

3. 完整的 reward 与 loss 定义

保留 PRM 原生双换行步骤格式，不移动步骤边界。设每步正确概率为 pt，错误概率 et = 1 − pt。沿用 LCA 的 Softmax-Weighted-Sum 思路，把整条解答的错误预测定义为：

w_t = softmax(e_t / T) T = 0.2，初始固定值 Eφ(τ) = Σ_t stop_gradient(w_t) · e_t 分数在 [0,1] 内

整条错误预测与单步错误标签不同。我们借用已有聚合，不把它算作新贡献。所有在线对照采用相同 T、相同 stop-gradient 实现。

L_wrong = mean_{verified-wrong τ}[ −log Eφ(τ) ] L_correct = mean_{verified-correct τ}[ −log(1 − Eφ(τ)) ] L_anchor = mean_{public labeled steps}[ BCE(p_t, gold_step_label) ] 对照 C：L_PRM = L_wrong + L_correct + β L_anchor 我们 D：L_PRM = L_wrong + β L_anchor β = 1.0，初始固定值；各项单独取均值，避免删除一项同时改变另一项尺度。

这就是唯一核心差异。删除的是“正确结局直接认证全部步骤”的弱监督项，真实公开的正确步骤标签仍通过 L_anchor 保留。C 与 D 必须保持相同错误样本数、锚点暴露次数和更新步数。

策略训练阶段，B/C/D 使用相同的简单序列奖励：

Sφ(τ) = min_t p_t R(τ) = 1[final answer verified correct] + λ Sφ(τ) λ = 0.2，主实验固定；R 经相同 GRPO 配方产生优势并更新策略。

结果正确的标量奖励仍高于错误结果，但这不是对参数更新方向或最终准确率的理论保证。过程分仅改变同一模型的训练偏好；是否真的提高解题能力由测试集判定。这里不引入新 token mask、树式搜索或额外续写。

4. 与最接近的工作有什么区别

已有工作我们直接沿用／承认的部分本项目单独检验的差异
LCA · 代码整条结局弱监督、MIL、SWS 聚合。论文已明确讨论正确结局伴随错误过程的单侧标签噪声，也做了噪声实验。采用不对称在线监督与固定已标注锚点，在策略变化的 RL 训练中比较；新贡献不包括发现噪声或首创 MIL。
PRIME · 代码复用策略生成的解答和结局标签，在线更新奖励模型。PRIME 从语言模型概率比得到隐式奖励。本项目调整显式步骤分类器的弱标签规则，重点比较 C 与 D；不把 PRIME 说成逐步错误标注法。
PRPO · 代码使用过程奖励改善数学 RL，作为强基线。PRPO 的主要改动位于优势构造。本项目更新评分器的监督来源，不改变 B/C/D 的 GRPO 公式。
PURE · 代码最低分及过程信用分配已有研究。论文提示 PRM 奖励投机风险。本项目不声称最低分聚合新颖；是否改善奖励质量必须通过同聚合、同预算的对照来检验。

项目的定位是针对一个有证据的标签问题，做可归因的小改进并测试其下游 RL 效果。文献有相近部件不是重新选题的理由；把已有部件完整计入基线，贡献只落在 C→D 的差异上。

6. 模型、数据与算力

策略Qwen/Qwen2.5-Math-1.5B，LoRA rank 16；所有组使用同一初始 checkpoint。
评分器HuggingFaceH4/Qwen2.5-Math-1.5B-Instruct-PRM-0.2；沿用现成 token 分类 head，在线组使用 LoRA rank 8。
训练数据MATH 原始 train 划出固定 500 题验证；其余用于 RL。首轮 pilot 固定 512 题；正式训练冻结题目 manifest 和顺序，不按方法挑题。
步骤锚点固定 2,048 条公开 PRM800K 已标注前缀，正确／错误尽量均衡。仅取训练问题；与验证、测试及 ProcessBench 按问题 ID 和规范化文本去重。它是额外公开监督，必须披露，不能称完全无步骤标注。
生成每题 8 条；temperature 1.0；max new tokens 2,048；有效每批 16 个问题；微批次从 1 开始。
框架TRL + PEFT + Math-Verify；PRPO 适配和 PRM 轮间更新采用受控自定义代码。冻结实际安装版本、模型 revision、配置哈希与每个奖励版本。
轮间更新每累计 1.2M 策略生成 token，暂停策略；用近期最多 512 条合格解答和固定锚点更新 PRM 32 个小批次，再恢复策略。C/D 的失败样本、锚点数与更新步数对齐。
正式规模每组每 seed 暂定 12M 策略生成 token；五组 × 三 seed = 180M token。首个 pilot 测出吞吐后统一冻结正式额度，可统一缩至 6M；不单独削减不利的对照。
硬件运行两卡时策略与 PRM 可分卡；单卡时分阶段加载、串行打分和更新。LoRA、梯度检查点、小微批次控制显存；不把两张卡当作一张统一显存设备。

初始资源上限：四周内合计最多 300 GPU 小时，含训练、PRM 更新、pilot 与最终评测。这是项目分配上限，不是已经测得的耗时；一天两卡各用一小时计两 GPU 小时。第一天只测基础流水线，再根据实测吞吐统一确定 6M 或 12M 的正式生成预算。暂不引入 7B 模型、API judge、MCTS 或额外续写采样。

公平比较同时给出两条横轴：累计策略生成 token 与累计 GPU 小时。单独记录 PRM 前向 token、PRM 反向 token、锚点暴露次数、策略更新次数和峰值显存。C/D 复用 rollout 不等于 PRM 更新免费。A 在等算力比较中可用节省的评分成本继续做策略训练。

7. 主指标与成功标准

  • 主要能力指标：完整 MATH 测试集的单次生成准确率。GSM8K 测试作为迁移评测；MATH500 仅附带列出，不能与完整 MATH 当成独立测试集。
  • 主要归因比较：D 对 C。各 seed 保存逐题成败，报告差值、种子离散程度和配对区间。预先固定最终预算 checkpoint 为主结果，验证集最佳 checkpoint 仅作补充。
  • 评分器机制指标：ProcessBench 首错识别 F1、全正确解答识别率，及“终答正确但有过程错误”子集的误放行率。阈值在独立训练来源验证数据上选择，禁止在 ProcessBench 上调参。
  • 训练健康指标：PRM 分数与真实答案正确率的分离趋势、输出长度、截断率、重复率，以及低分／高分塌缩。过程分升高本身不算成功。
  • 有价值的主结果：D 相对 C 有跨 seed 的能力收益，并且相对 A/B/E 中的强对照具备准确率或等算力优势。PRM F1 单独上升只能支持评分器结论，不能宣称数学能力提升。

假设只有两条：H1，不对称监督减少正确结局对错误过程的错误认证；H2，这种改进能转化成下游策略的单次解题准确率。现有论文与公开数据支持研究 H1 的动机；两条假设都尚未由本项目训练验证。

9. 可以直接带进组会的说法

我们做小模型数学 RL，研究“结果奖励如何可靠地帮助更新过程奖励”。现有弱监督方法会把答对的解答当作全程正确，但公开 MATH 过程评测里确实有答案正确、推导错误的例子。我们只改在线评分器的一条监督规则：失败解答提供“至少一处错误”的信号，成功解答不自动认证全部步骤，再用一小份公开步骤标签保持评分器稳定。然后在同一 GRPO 系统里对比冻结评分器、普通在线更新和我们的更新方式，看最终模型自己做题是否更准。

10. Proposal 可用英文摘要

We study whether asymmetric outcome supervision improves online process-reward adaptation for small-model mathematical reasoning. Outcome-supervised reward learning often treats a correct final answer as evidence of an entirely valid reasoning trace, although correct answers can contain intermediate errors. We adapt a pretrained explicit process reward model using verified failed policy rollouts as weak evidence that a complete solution contains at least one error, while withholding all-correct pseudo-labels from successful rollouts. A fixed replay set of public step annotations provides both correct and incorrect anchors. The adapted rewards are combined with verifiable outcome rewards in an otherwise unchanged GRPO pipeline. We isolate the proposed supervision rule against symmetric online adaptation, a frozen process reward model, outcome-only GRPO, and a budget-matched PRPO adaptation. Evaluation prioritizes single-generation accuracy on MATH and transfer to GSM8K, with process-error identification and compute-accounted learning curves as supporting analyses. Our contribution is the asymmetric adaptation rule and its controlled downstream evaluation, rather than online reward modeling or weak-supervision pooling themselves.
