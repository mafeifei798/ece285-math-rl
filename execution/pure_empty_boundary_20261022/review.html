1. 根因究竟在哪

  1. 模型层：9 条真实空回答在冻结 Qwen PRM 上均得到极高正类分数。逐条按 Qwen 官方示例直接 forward，与接入层的批量评分最大差异只有 0.0000284，无法解释高分本身。
  2. 接口层：我们的 steps or [''] 会建立一个空的末尾评分边界；但 Qwen 示例的 join(steps) + marker 在空列表时也会产生同一个 marker。288 条输入的原生 token 序列逐条一致。因此删除这一行并不能证明已修复模型。
  3. PURE 层：固定官方版本会给末尾 EOS 建立评分边界。高正类分数经过签名变换与 soft-min 后，空回答得到接近 +0.5 的任务奖励。RLOO 正确地使用了一个语义上有问题的分数。

PURE 论文 §5.1 Case 3 已讨论空回答与无关短句拿高分，并使用少量最终答案监督缓解。该现象并非 Qwen 独有，也不是换成 PURE 自己的 PRM 就有保证消失。论文原文 · Qwen 官方接口

不能倒推旧 B 的失败原因：旧 A/B 的这 9 条空回答没有被 PRM 评分，原奖励均为 0。此次发现是 PURE 纯过程奖励接入后的风险，不能用它解释旧 B 为什么不如 A。

2. 为什么“空回答奖励清零”不够

PURE 使用有正有负的过程奖励。若其他回答的过程回报为负，空回答的 0 仍可能高于基线；经过 RLOO 和唯一一次 whitening，仍可能鼓励 EOS。下面是对已保存回答的数值反事实回放。

3. 已实现的最小保护：两组共同暂停，不改奖励

独立版本 GuardedPureIntegration 在生成后、准备信号前与 backward 前检查纯空白回答。若发现，保存完整批次、实际 token 与原因，然后抛出明确异常，停止本次更新。

  • 同一规则作用于 P-VR 与 P-PRM。不删除空回答，不偷偷补采，不清零或设负奖励，也不改变 loss mask。
  • 正常回答原样走旧实现。32 条精确 token 回放中，两组的步骤位置、reward、return、advantage 均逐项一致；loss 对 log-prob 的梯度差异为 0，whitening 仍只有一次。
  • 不会把语义判断伪装成格式检查。“Thank you.”、无框答案、单数字仍是非空内容，不被这条保护过滤；它们的 PRM 风险仍存在。
  • 这是一条实验停机规则，非 PURE 官方奖励算法。若以后任何一组触发，不能把不同训练预算的结果冒充完成的公平对照。评测时仍保留所有空答案，按原验答器计分。
已解决：空回答不会在这个独立保护版本中悄悄进入参数更新。
未解决：PRM 对空内容／无关内容的语义高分。停机不等于把评分器训练好了。

4. 正式实验如何保持标准与公平

保留 P-VR / P-PRM 原定义。同一策略初始化、题目、采样、token 预算、KL、RLOO、PPO 和验答器；当前独立保护也相同。原 A/B 与原 PURE 联调证据全部保留。

若要使用已有的、针对该问题的训练方案，官方提供的是独立命名的 PURE-PRM+VR。其步骤奖励与最终答案奖励在 token 层结合，再走同一官方优势计算。它可作为单独的标准比较，不能悄悄取代 P-PRM。本次只做离线反事实，未安装混合训练入口。

即使所有展示题都提供 GT，8 条中仍有 7 条的归一化空回答 advantage 为正。因此不能承诺“加上官方混合就彻底修好了”。要保证空回答被负向学习，需要明确改变任务完成约束、奖励或 PRM；这些都超出纯接入纠错。

当前判断：接入基本正确，纯过程目标的边界风险已证实。保留标准 baseline，采用共同停机保护；不把自定义空回答惩罚塞进 baseline，也不据此启动纯 P-PRM 长训练。

5. 证据、成本与限制

取所有含空回答的历史 update 批次，共 9 × 32 = 288 条，对冻结 7B PRM 重新评分。没有加载策略模型，没有新采样，没有优化器。GPU 阶段含加载共约 138 秒，峰值 Torch allocated 13.90 GiB，reserved 15.31 GiB；进程已退出。
