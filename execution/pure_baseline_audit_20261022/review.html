2. PURE 实际怎样把奖励变成训练信号

应以以下整条路径作为基线，不能只把当前 B 的最低分换个名字。

  1. 原生步骤打分。Qwen PRM 在每个 <extra_0> 给出正类概率 p；按 PURE 源码转换为有符号分数 r = p − (1−p) = 2p−1。
  2. 近似 min-form。对一条回答的各步骤计算 ws = softmax(−rs/0.1)，并取 qs = wsrs。低分步骤权重大；有限温度时不是硬取最小值。
  3. 放回 token 位置。将 0.5qs 放在该步骤的最后一个 actor token，其他位置过程奖励为零。0.5 来自固定官方 YAML，而不是继续沿用旧 B 的 0.2。
  4. 先加入 KL 约束，再累计回报。使用官方 low_var_kl，系数 0.001；从后往前累计，γ=1。P_PRM 没有答案正确奖励；P_VR 则将原验答奖励放在最后一个有效 token。
  5. 官方 RLOO。每个 token 的累计回报减去同题其他 7 条回答的 token 回报均值。分母使用固定填充宽度 N=2048，不改成每条真实长度或 batch 动态最长长度。
  6. 一次 masked whitening 和 PPO loss。在整个 32 条回答生成批次的有效 token 上做一次 whitening，再分成 microbatch。使用官方 clipped PPO 函数，ε=0.2；不再经过 TRL 原有的标量奖励组标准化，也不再添加第二份 KL loss。
原 B：步骤概率 → 整篇最低分 → 加答案奖励 → 整篇一个 advantage
PURE：有符号步骤分 → soft-min → 步骤末 token 奖励
      → 各 token 的后续回报 → RLOO / whitening → 逐 token advantage

例：三个步骤的 p=[0.9,0.1,0.8]，对应 r=[0.8,−0.8,0.6]。soft-min 几乎集中在第二步，最差步骤之前与之后的回报因此不同。“最差步骤之后回报接近零”不等于其最终 advantage 为零，还要考虑 RLOO baseline 和 KL。

直接依据：步骤分及 soft-min；return 与 RLOO；奖励、KL、优势的执行顺序；masked whitening。

4. 最小而公平的实验组合

组别训练目标用途 / 状态
A_GRPO原结果奖励 GRPO已经完成，原样保留
B_MIX原结果＋最低过程分 GRPO已经完成，原样保留
P_VR官方 PURE/RLOO 核心，只使用原验答结果建议新增的配套控制；尚未启动
P_PRM同一核心，只使用现有 Qwen PRM建议新增的过程奖励基线；尚未启动

主比较固定为 P_PRM − P_VR。两组共享初始化、数据、提示词、RLOO、KL、学习率、loss、长度与生成预算，仅外部任务奖励来源不同。这样避免把 GRPO→RLOO、学习率或 KL 的变化误认为 PRM 的收益。

原 A/B 与新 P 两组仍可并排报告端到端准确率和成本，但属于整套训练配方比较。若以后要单独证明 min-form 的贡献，才增加同一 P 管线的 signed sum-form 消融；这不是本轮必须增加的训练。

不把“PURE-PRM+VR 的 10%”理解成给结果项乘 0.1：论文对应的是仅约 10% 题目提供可验证答案。首轮暂不引入该混合设置，避免额外的数据／奖励覆盖差异。

7. 源码与论文之间需要明确记录的细节

  • 公开默认不是一张卡。YAML 是 8 GPU、prompt batch64、8 rollouts、completion7168；论文写最大生成8192。单卡方案缩短长度、缩小生成 batch，并保留 LoRA，这是明确的规模适配。
  • 默认主路径是 RLOO。论文附录确有 GRPO 版本，但不能在当前 TRL 上把步骤分数塞进普通标量 reward callback 就称作该版本。
  • 代码将任务奖励与 KL 先合并，再统一计算 return/RLOO。论文式(7)把结果项与过程项的 baseline 分开写；公开 verl 路径不完全照此拆分。本方案以固定源码执行顺序为准，不把两套写法拼成第三种实现。
  • 固定 padding 的 N 有数值作用。官方 token RLOO 也作用在 VR 上。例如 K=2、N=6、长度2/4、结果1/0，错误回答在 whitening 前的优势是 −1/3，而普通整句 RLOO 是 −1。CPU 已验证这个差别，因此必须有 P_VR 配套控制。这里记录行为，不擅自把它“修正”为自己的算法。
  • 官方入口会强制设置提示词。main_ppo.py 强制加入“步骤用双换行分隔”的提示；本方案保留原 A/B 提示词，并明确标为协议适配。
  • 默认开启课程筛选。为了固定数据与预算，本方案两臂均关闭；不能让新方法悄悄多一个选题机制。
  • 学习率并非一份唯一官方数字。公开 YAML 默认1e−6，论文 PRM-only 主实验为5e−7。新两臂先统一公开默认1e−6，不根据测试结果调参；旧 LoRA A/B 是5e−6，因此新旧只是整套配方比较。

来源：官方默认配置；强制 prompt；统一奖励路径；论文 v3 §3.4 / §4.2 / App. F.2。

8. 放行条件与公平比较

  1. CPU 数学核对已完成。其余步骤尚未执行：真实 tokenizer 对齐、模型无更新前向／反向、显存与吞吐测试。
  2. 先无更新联调。同样 4 题×8 回答，长／短回答、CRLF、无分隔符、EOS、截断、空输出都覆盖。允许反向计算但不调用 optimizer.step；前后参数 hash 必须相同。正式训练必须等用户另行授权。
  3. 检查是否混入答案监督。P_PRM 中打乱 gold answer 不应改变训练 reward/advantage；P_VR 则应跟随 outcome 改变。不得通过验答状态决定 P_PRM 是否打分。
  4. 统计粒度固定。whitening 在完整生成 batch 上做，不能在 microbatch 上做；N固定2048；优势、mask、token ID 同步打乱和切片，检查 loss 入口张量原样保留。
  5. 生成预算和成本分开。各6M completion tokens，另外报告 prompt tokens、PRM原生／padding输入tokens、评分时间、actor/reference前向次数、更新次数、实际 GPU 时间。等生成tokens不是等总算力。共享GPU的墙钟耗时不作效率证据。
  6. 评测不追着结果改。最终固定checkpoint，原验答与prompt。报告正确／可解析但错／缺框／截断，以及长度、步数、重复、答案框与正文不一致的实例。配对bootstrap按题目抽样；seed17只能作先导结果。
  7. 数据边界写清。保留当前训练与评测去重清单。原 PRM800K inventory 审计不能证明 Qwen PRM 的全部训练数据无污染；既有验证／测试已用于诊断，不宣称完全未见或盲测。不拿它们挑最佳超参数或 checkpoint。
最终建议：不用继续换 PRM，也不把旧 B 改名覆盖。先实现并无更新验收一套来源明确的 PURE RLOO 核心适配版，之后若获准训练，仅成对运行 P_VR 与 P_PRM。这样才有一个能够回答“可靠过程训练机制下，现有 PRM 是否有帮助”的基线。
