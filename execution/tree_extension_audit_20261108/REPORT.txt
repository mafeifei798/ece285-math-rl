树状 rollout 与 C-bounded：原文、代码及可行性审查
2026-11-08｜状态：文献与 CPU 公式核验完成；未启动新训练或 GPU 联调

建议
支持把树状信用分配作为下一项有边界的扩展。现有 C-bounded 结果继续作为项目基础；主问题改为：来自同策略树状续写的结果信用能否改进当前模型，固定的 C-bounded PRM 偏好是否还能提供额外价值？这是 TreeRL 启发的扩展与受控实证研究，不应声称发明树状 RL，也不能预先承诺明显提高准确率。

为什么值得试
此前“首错前缀保护”相对均匀减罚只有 +0.2 个百分点，区间 [-2.0, 2.6]；固定长度分母相对原 C-bounded 为 -0.6 点，区间 [-3.2, 2.0]。这些结果没有确认继续调局部惩罚/长度分母的价值。树状方案真正改变了探索和信用的来源，技术改动更实质，但需要验证它在我们的 1.5B/2048 上限下是否有效。上述是验证集短续训结果，不能据此断言对应方法普遍无效。

1. PROGRS 查重：接近，但不等同
已读 v2 的 III-A 及官方 training/comput_advantages.py。两者都把过程项加在结果优势后面，但处理对象不同：
  PROGRS：正确回答保留原始过程分；错误回答减去错误子集均值。
  C-bounded：错误回答过程项恒为 0；正确回答过程项为 0.2 × (该回答的最小 PRM 分 − 正确子集的平均最小分)。
因此 PROGRS 在全错组仍可能给某些错答正的过程优势；我们的版本不会。共同的“结果约束过程信号”思想应明确引用，C-bounded 的区别是具体的正确子集有界偏好及失败机制，而非这一宽泛思想的新颖性。
来源：https://arxiv.org/html/2604.02341v2#S3.SS1
代码：https://github.com/NIMI-research/PROGRS-Process-Reward/blob/22d4bff79949d850bd8f713e33547f78107d7e95/training/comput_advantages.py

2. TreeRL 核对：可以借鉴，不能直接替换一行配置
官方分叉指标是已采样 token 的 -log p(token|prefix)，即惊讶度；不需要另算 top-k 近似分布熵。前缀严格截止在选中 token 之前。共享前缀在多条叶子序列中重复训练，论文为此使用子树叶子数的平方根降权；这不是完全去重。官方代码还涉及 RLOO 预处理和所选叶子的计数，移植时必须核对这些额外步骤。
官方脚本是 Ray 多节点多卡的 Qwen14B 配置。我们的单 A100、TRL、LoRA 版本需要独立移植，准确名称应是 TreeRL-style rollout/credit，而非完整官方复现。论文 Table 1 中 Qwen14B 的 MATH500 是 81.6→81.7，不能据此保证我们的 1.5B 会大幅提升。

3. 必须纠正的机制表述（本轮 CPU 算例已核验）
全错树仍无结果信用：如果八片叶子全错，所有节点的后代成功比例都是 0，全局/局部优势均为 0；正确叶子 PRM 项也为 0。分叉可能找到正确续写，但不能凭空解决全错组。这里只说策略优势；KL 正则仍可能产生更新。

共享前缀可以获得正信用，即使其中一条最终续写答错。算例中整题成功率 1/2，某共享前缀的四条续写三对一错；该前缀优势是 +0.25，错误续写独有后缀是 -1.25。这是树方法有意保留有用前缀的行为。新版本的保证应是“错答无正 PRM 项”，而不是“错答的每个 token 都非正”。

整条回答的最小 PRM 分不能自动定位到叶子独有后缀。如果最低分出在共享前缀，把整条分数偏好加在后缀上，是额外的归因假设。第一版只把它称为末端的有界辅助偏好，记录最低分所在区域，并通过 tree_vr / tree_cb 对照判断其增量价值；不能宣称它提供了正确的逐步数学监督。

节点成功率是这棵自适应采样树上的经验量，不是数学步骤正确性的证明，也不保证是原策略价值函数的无偏估计。相关续写和答案碰巧正确的问题仍然存在。

4. 收缩后的最小版本
  树形状：(M,N,L,T)=(2,1,1,3)。先生成两条独立完整回答；每条选一个合格分叉点，保留原后缀并增加三个续写，共八片叶子。仅一轮扩展，不加 MCTS，不让 PRM 选择分叉点。
  生成规则：保持现有提示词、采样设置与验答器；必须用原始 token。每条完整路径（前缀＋新增后缀）总长不超过 2048，不是给后缀额外 2048。两轮生成之间不更新策略。
  结果信用：从叶子正确性算节点的全局/局部信用，并明确实施共享前缀权重；不再标准化已经构造好的 token 优势。
  PRM 项：维持当前 0.2 正确子集居中的叶子偏好，只加在叶子独有段，错答为 0。该投影是待验证选择，不是旧 C-bounded 目标的严格等价变形。
  其余：保留原 grpo loss reduction、LR=5e-6、KL=0.04、原 C PRM 适配器和验答规则。树信用本身改变了优势构造；这是一项新实验，不是修 bug。

先建议一个三组短续训方案（尚未启动/排队）：
  chain_cb：原链式 C-bounded，作为继续训练的控制组。
  tree_vr：树状 rollout＋只来自最终验答的树信用。
  tree_cb：与 tree_vr 相同，再加上述固定有界 PRM 项。
三组均从同一个现有 C-bounded checkpoint-288、同优化器/调度状态开始，各 48 次更新，seed17，保持同题序、每次四题及每题八片叶子。chain_cb→tree_cb 衡量整套扩展；tree_vr→tree_cb 隔离 PRM 的额外作用。不能把前一差值解释为单独某个机制，也不能用这个“从 C checkpoint 续训”的 tree_vr 冒充从初始模型训练的 A。

先固定叶子数和更新次数，分别报告实际唯一生成 token、展开后训练 token、PRM 输入 token与墙钟；这不等于精确匹配生成 token。若后续研究固定 token 预算，应单列效率实验，允许更新次数随实际长度变化。完整的“链/树 × 结果/过程”交互结论需要同起点的四臂设计；本次三组局部试验不承担该结论。

5. 代码与验收
可复用 experiments/prefix_protection_20261107/token_loss.py 的 [B,T] 优势接口及 native_sync.py 的 LoRA 同步。当前 runtime_mixin.py 先生成八条独立回答，再覆盖优势；树采样必须进入更早的原始生成路径，不能只改 signals。其第 47 行还断言错答所有 token 非正，需要独立的 TreeRuntimeMixin 及分量检查，不能修改历史类或删除原保护规则。

正式更新前必须做真实模型无更新验收：前缀及 log-prob 来源、分叉 token 的因果边界、总长度/EOS、重复前缀权重、优势从构造到 loss 的 fingerprint、padding、所有模型 hash。记录 PRM 低分在共享前缀还是独有后缀；测显存和吞吐。当前 16 个 CPU 检查只验证公式边界和人工 token 的映射，不代表真实模型集成已通过。

短试后只看同一次共同验证集评测，报告配对胜负与区间。+2 点可作为工程筛选线，不能当作统计确认；已有源 checkpoint 跨轮贪心重评出现过 0.4 点净差，原因未定位。不要声称已反复看过的测试集是全新封存测试。短续训无效只说明本项目当前预算不值得扩，不能证明从初始模型训练的树方法无效。

6. 预算修正
五次已完成短试总计 5,114,714 个生成 token、25,719.0865 秒，折合约 1.397 小时/百万 token 的单卡作业墙钟。这是历史链式/本地运行时数据，不是树状吞吐实测。
原两组各 3M 筛选，再把两组两个 seed 都新跑 6M，共 30M，链式时间参照约 41.9 小时。若 seed17 的 3M 直接续到 6M，总量 24M，约 33.5 小时。若只确认一个选中变体，复用其 seed17 3M，总量 15M，约 21.0 小时。均未含评测、排队和工程。
因此不能承诺 12 小时跑完整套。三组 48 更新仅按旧短试折算约 4.2 小时训练参照，另加真实联调与共同评测；树的速度、共享卡负载及峰值显存须实测。论文也明确区分“相同生成成本”和“更多训练计算”，共享前缀并不自动让端到端成本更低。

7. 新意与状态
检索还找到 PRM 引导树状 rollout 的 PATR，虽是 agent/多轮场景而非这里的末端有界项，仍说明“树＋PRM”不是空白。针对性检索尚未核实到完全同式的正确叶子后缀偏好；这不等于查证不存在先例。项目可以以单卡实现、失败边界和公平的 PRM 增量比较体现含金量，不包装成已证实的新算法。
