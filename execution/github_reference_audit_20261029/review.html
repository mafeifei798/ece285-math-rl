最值得吸收的结论

PAPO是最接近的方法对照，PURE用于信用分配核查，EasyR1用于工程参考，LCA用于核对PRM适配来源。“只在正确样本中使用过程项”已有明确先例；当前要验证的是信号缩放在现有小模型/判别式PRM设置中的作用。

与PAPO的关系

固定commit的核心函数先构造结果优势，再仅在正确子集中构造过程优势。默认按各自std缩放；同一开关也支持两项均只减均值。

PAPO default:  A = standardized(y) + lambda * y * standardized(m | correct)
Current:       A = standardized(y) + 0.2 * y * (m - mean_correct)
PAPO no-std:   A = centered(y) + lambda * y * (m - mean_correct)
门控和优势解耦不是我们的原创；PAPO也已有不除std的代码分支。我们的混合缩放与该分支不同，但不能仅凭这一处变化宣称独立新算法。当前三臂是初步机制验证，尚未证明优于PAPO。

源码函数使用固定lambda；脚本头部仍有adaptive clipping的旧注释。评估方法应看实际执行路径。PAPO的生成式grader、多卡和8192长度也与当前单卡、判别式7B PRM、2048长度不同，公开精度不能直接横比。

可落地的参考边界

PAPO

可借鉴：精确对照正确子集门控、过程项缩放、活跃组比例；当前三臂不会改动。

限制：默认配方需多GPU及额外生成式grader；不能直接照搬到单A100，也不能把我们的门控说成原创。

PURE

可借鉴：保留step/token baseline、EOS、重复/截断等诊断；分支和提交号必须固定。

限制：verl的compute_return(min)仍有作者TODO注释；仅凭注释不能断言整条路径有bug，使用前要逐例回放验证。

PRIME

可借鉴：借鉴多奖励源分开记录和成本核算；引用时区分隐式PRM与显式判别式PRM。

限制：引入完整在线PRM更新会改变当前固定C实验，不作为本轮迁移目标。

PRPO

可借鉴：学习分段到token映射与中间张量检查；优先核对具体manager入口后再复现。

限制：根README缺失；一些基线分支使用±1及长度惩罚，不能把原仓库结果当作与我们的0/1协议同条件。

PROF

可借鉴：借鉴Blend可能低于GRPO的对照思路及过程质量评估。

限制：不能作为即插即用实现；报告主要是temperature1的average@16，不能直接和我们的greedy数值比。

LCA

可借鉴：核对pooling、detach、ProcessBench和BoN的评分定义。

限制：它是奖励模型训练框架；完整LCA训练或其理论保证不等于我们的少量LoRA适配，更不等于策略数学能力提升。

SimpleRL

可借鉴：借鉴纯结果奖励基线、checkpoint对比和多基准解答审阅工具。

限制：README所列部分base与RL模型解码设置不同；发布分数不能直接与当前统一greedy实验横比。

Dr.GRPO / Understanding R1-Zero

可借鉴：固定模板、初始化、KL、长度上限和评测协议，把模板因素与算法因素分开。

限制：此轮不更换成Dr.GRPO，否则改变A以及全部实验的训练目标。

EasyR1

可借鉴：借鉴配置组织、LoRA部署和恢复工具；把accuracy/format/overall分开记录。

限制：现有A不允许加格式奖励；估算显存不包含我们额外的7B PRM，不能用表格替代实测。

DAPO

可借鉴：关注有效组比例、截断、token预算和各消融组件的成本。

限制：当前单A100项目不移植其完整大规模recipe；没有读取到的配方不冒称已逐行核对。

TRL

可借鉴：在buffer/shuffle之前构造并标记优势，在loss入口核验；固定版本，防止多次归一化。

限制：不把最新main分支当作当前0.23.1实现，也不在运行中升级库。
