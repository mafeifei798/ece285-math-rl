2. 代码与数据可以修的部分

2.1 优势核对断言的数值稳定性（不改变训练目标）
位置：training_b/train_b.py:63-67；training_b/prm_reward.py:95-100。
B 上次退出直接发生在 CPU 独立优势与 TRL GPU 优势的精度比较；该失败批次没有完整保留，不能声称已经逐位重现。

建议实施：
* 保留 TRL 实际用于 loss 的优势张量，保留组内 sample std、epsilon=1e-4 及 reward 公式。
* 审计显式记录实际奖励张量、设备、dtype、分组、均值、标准差、实际优势和参考优势。
* 主要公式核对使用与实际路径一致的设备、dtype 和归约方式；另用 float64 参考及近零方差用例检查误差来源。
* 在已有保存批次和零方差/近零方差的合成回归用例上验证，再固定数值容差；不根据后续训练能否通过临时加大容差。
* 在任何致命断言之前保存失败批次；保留 NaN/Inf、错误分组、非法概率、错位和超出已验证误差范围的停止保护。

验收：实际进入 loss 的奖励及优势未被补丁重写；有限值、组大小、std 口径和异常检测通过。
仅这类诊断补丁通过验收后，未来才可考虑从 B checkpoint-660 恢复，并保留补丁哈希与恢复收据。
已保存 checkpoint-660 的训练记账为 13,853,973 tokens；不能将未保存的后续更新算作该 checkpoint 已学习的进度。实际重算消耗另记。

2.2 百分号/答案单位口径（无需训练 PRM，但会改变结果奖励）
位置：training/reward.py:14-34；当前接口只有 prediction/gold，不能按题目判断单位。

建议实施：
* 数据准备阶段增加冻结的 answer_type/answer_unit 元数据，依据题意与标准解确定，不依据策略当前回答推断。
* 验证器将预测和标准答案转换到同一单位再比较，保留原始文本、转换记录及判分原因。

  - 问百分之多少、gold=20：20 与 20% 按百分数值单位接受；0.2 不自动当成 20。

3. 必须改进 PRM 的部分

“正确数学低分、明显数学错误高分”在当前已对齐的输入上仍成立，不能靠调整 token 索引或百分号处理修好。
错答的绝对分数降低，也不等于组内学习信号变好；目标是改善数学有效性与相对排序。

建议保持原方法，先补足既定适配设置的覆盖与验证，不增加新 loss：
* 离线缓冲区继续来自同一个冻结初始 actor，使用原计划固定 512 题×4 回答；不换成只针对 B 错例的 D 专用数据。
* 使用原计划 2048 条真实步骤标签锚点，正负类别均有覆盖，核对前缀和标签位置。覆盖题型、长度及可获得真实标签的解答形式，而非只重复少数失败回答。
* 终答正确不自动标每一步正确；终答错误也不自动标每一步错误。公开步骤标签提供定位，整条成功/失败只提供既定弱监督。
* B 仍为原始冻结公共 PRM；C/D 同一原始 PRM、相同适配器初值、缓冲区、锚点批次、步数、优化器、学习率和各项归约。
* C = L_fail + L_success + L_step；D = L_fail + 0*L_success + L_step。
* 补齐 S = L_step 的 PRM-only 诊断。S 不增加 RL 臂，匹配锚点批次、初始化、优化器、更新次数和锚点系数。

为何有可能有效：
失败弱监督只能表达“这条解答至少哪里有问题”，自身不能确定错误位置；D 又没有成功弱监督项。
真实正/负步骤锚点可同时约束有效推导的接受与错误步骤的识别，减少只学会整体压分的退化。
但 D 已经使用锚点，pilot 仍未显示排序优势，所以“用足原定锚点/覆盖更广”是待检验的稳定化措施，不是已经证明的解法。
不因本次负结果直接认定扩大数据必然有用，也不以新超参替 D 制造胜出。

若将来必须调适配强度：
只能在单独、无评测重叠的训练开发集上确定一套 C/D 共享设置，再冻结。
例如共同更改学习率或锚点系数，必须声明为新的探索性版本，并在同设置下重做 C/D/S PRM 对照；不能只调 D。
本方案先保持 beta=1 等既定设置，没有选定新权重、没有调参或训练。

PRM 验证重点：
* 有真实过程标签的开发集：正确链接受、首错定位、有效/无效排序，报告类别数与题目配对区间。
* 相同策略轨迹组：比较 B/S/C/D 的排名及实际 GRPO 优势，按全对、全错、混合且是否含无效输出分层。
* 人工核查的明确错误案例不能继续作为“分数降了就成功”的例子，要看排名与优势；错终答但有用前缀不一概算奖励错误。
* 已看过的 50 条和 ProcessBench pilot 用于回归/诊断，不喂入 PRM，也不用于选权重、阈值、checkpoint 或 seed。正式评测如包含这些样本，披露先前暴露并另报未使用部分。
* PRM 指标改善不等于策略数学能力提高；后者仍要靠匹配的 RL 与独立单次答题评测。

4. 这轮不改 GRPO 目标或奖励聚合

共享主设置继续为：
  A：R=y
  B/C/D：R=y+0.2*min(p_step)
  A/B/C/D：相同组内标准化、std 口径、epsilon、有效输出/截断规则。

所有回答有效且结果奖励相同的组中，
  advantage_i = (m_i-mean(m))/(sample_std(m)+5e-4)。
因此把 0.2 改得更小主要不能可靠限制这类组的过程优势；非退化组中分数差和标准差会一起缩小。
把所有分数压低同样不能保证纠正相对排序。0.5 是诊断阈值，不是实际连续奖励的开关。

此时不关闭标准差归一化、不将 min 换 mean、不对全错组清零、不插入 D 专属 mask。
这些都属于额外的训练算法改动。未来若研究，须另立匹配的奖励/归一化对照，不能归功于 PRM 的 c 开关。
完整错答可能有正过程分、无效输出为零的共同规则继续披露，A 对其他臂的差异包含这一因素。

恢复/重用规则：
* 只有诊断/日志修复：验证目标未变后，可以保留旧 A，并在未来获授权后从 B 的完整 checkpoint 恢复。
* 只做共同重评估：可保留旧模型，用新旧验证器对同一保存预测复算；不声称修复了旧训练。
* 改结果奖励、排除训练题、改 PRM 切分/输入或改 GRPO：另建执行版本，冻结 manifest/哈希和补丁理由；不能接着 B 半程更改规则后仍称全程同一干预。
* 改训练期结果验证器/训练数据/四组共同 GRPO 目标，会影响四组。旧 A 不能直接充当使用新规则训练的 B/C/D 的严格对照；统一重评估也不能消除训练历史差异。
* 若仅改 PRM 输入分段，A 不用 PRM：确认 A 的数据、结果验证器、提示、初始化、预算及其余目标未变后，可以复用已有 A，不必为版本名变化而重训。B/C/D 必须使用一致的新过程输入规则；旧 B 不能直接充当新输入 C/D 的严格原始 PRM 对照。
* 若仅对 C/D 共同调整 PRM 适配设置、其余奖励管线保持不变，A/B 的干预定义未变，可在兼容性核对后复用；C/D/S 则按共享新适配设置配套验证。
* 完整四组结论要求训练配置和相应干预一致、共同初始策略与公平预算。复用未受影响的臂要有逐项兼容凭据，并对所有保存模型采用共同评测口径。
