两组到底是什么

P-VR：原验答器二值结果 + 官方序列 leave-one-out。P-PRM：官方 PURE 7B PRM 的原生 BF16 两分类 logits + signed softmin + 官方 token baseline。两组共享同一批原始生成、actor/reference、边界和 PolicyLoss；不混入旧 B 的 0.2×min 奖励。

原始 emitted IDs 与官方 processed IDs 分开保存。被截断的输出即使由官方路径补入 EOS，仍按原终止状态交给原验答器，不因此变成有效答案。PRM→actor token 使用官方离散 token 边界，无 CRLF 重写或重新编码推导。

实现范围与限制

  • 官方 openrlhf commit 41f9363b8cc4af044b7fc5f7f9bbbf62139e9553，PURE PRM revision b0cce6763f2317762c9cb46720c8fe7b07f44a88。
  • 复用经 AST 和源文件 hash 校验的官方信号函数；模型/LoRA/vLLM 初始化仍用当前可运行的 TRL 后端，其 reward、loss、train、optimizer 路径被禁止。没有跑完整 Ray/DeepSpeed 分布式程序。
  • 1.5B actor、LoRA r16、32 条、2048 token 上限、原数据/提示词/验答器是明确的资源与协议适配。
  • 初始零 LoRA 下 old/reference 相同；真实非零 KL 未覆盖，非零 KL 由 CPU fixture 验证。
  • 仅验证一个固定 batch，不据此选择模型、估计泛化准确率、宣称解决空回答或 PRM 漏判。
  • 没有启动正式训练；没有改原 A/B 和 veRL 结果，也没有新增奖励或 loss。
