本批两个相关题目组都是 8 条全错，结果奖励留一项 yᵢ − mean(yⱼ, j≠i) 全为 0。 因此仅给这些组加上标准答案，结果奖励的这一项不会抵消三条 PRM 正信号。这里计算的是固定样本上的分量，不是声称完成了混合训练或完整混合归一化回放。 CPU 检查凭据

4. 换 PRM：可以检验，不能预先保证更好

优先候选仍是服务器已有的 Qwen2.5-Math-PRM-7B。旧离线审计中它也给 9/9 空回答高正类分数（0.9982–1.0000）； 部分非空短错答评分降低，另一些反而升高。目前三条的题目和输出都不在旧比较集里，因此不能把旧结果当作它能修复本批的证据。

旧审计用了重构 token，其中的 advantage 来自另一条回放路径；不能冒充本次原始 token OpenRLHF 的直接比较。 旧证据 · 适用边界

  1. 先固定当前完整 32 条批次，再预先选一个独立完整批次作为复核集。保留每题 8 条关系和原始 actor token、边界、old/reference log-prob。
  2. 各 PRM 用自己的官方输入接口。Qwen 需要 chat template 和 <extra_0>，不能照搬 PURE 的换行评分头。步骤映射失败必须报告，不能重写 actor token。
  3. 新分数通过相同 signed reward、softmin、baseline、KL、一次归一化和 loss 权重做 CPU 回放。模型及必要的输入适配器是唯一被替换的部分。
  4. 先要求三个确认无有效推理的坏例不再获正回答平均优势，同时核对正确短答和有效推导，防止只把所有分数压低。再看独立批次的错误强化、错罚和排序；样本太少则报告不确定。这里不要求所有终答错误的 CoT 都为负：有数学进展的错误解答仍可能值得相对鼓励，重点是已确认没有有效推理的输出。
  5. 通过后才值得提出新的配对小试验；未通过就不新开 PRM 训练。不能拿这些诊断样本挑完模型后，声称已证明泛化或下游准确率提升。

5. 复现边界和当前决定

当前分支 HEAD 仍为 41f9363b，与本项目 pin 一致。奖励、baseline、边界与归一化遵循该 OpenRLHF 路径； 整个实验应称为早期官方 OpenRLHF 算法的单卡 LoRA 适配，不是论文 v3 的完整训练复现。 v3 使用 veRL；当前小批量、长度、LoRA 和提示词与原配方不同。尤其当前提示词保留本项目协议，没有官方显式要求双换行分段的句子。 这些差异会影响输出分布，不能声称官方完整实验会以相同频率产生这些坏例；当前不能中途更改。

同输入、logits、组和 mask 下，官方信号路径会保留观测到的正优势。我们已排查这些样本的计算链，尚不能把它升级为“所有性能差异都已排除实现影响”。 此前 LoRA 到 BF16 采样副本的微小更新舍入限制仍需在最终结果中披露。

行动决定：完成已经批准的有上限配对 pilot 和共同评测，沿用既定停止规则；不加拒答罚分，不靠长度过滤，不改当前 PRM，不扩到 6M。 替换 PRM 的下一步是上述完整组离线准入检查。无可靠评分器时，不能把单纯改优势公式当作数学正确性的修复。
