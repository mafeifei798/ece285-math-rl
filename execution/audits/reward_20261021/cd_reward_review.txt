C/D 适配与奖励机制审阅 — 2026-10-21

本文件是 B 6M 审计之后的分析和后续建议，不覆盖已锁定的 protocol_simple.json、proposal 或任何训练代码，也不授权或启动训练。

明确建议
保留 A/B/C/D 主实验的奖励、分段和 GRPO 标准化。先按原定义准备 C/D 和 PRM-only 的 S，在同一份独立 probe 上检查评分与实际优势。奖励标准化的修改放在单独的敏感性实验，不只替换 C/D 的实现。

一、C/D 能解决哪一部分
原目标：
  C: L_fail + L_success + L_step
  D: L_fail + 0 * L_success + L_step
  S: L_step（不增加 RL 臂）
每个损失项分别取均值；删除成功项后不得重新平均其余损失。失败批次、成功批次、锚点批次、初始 PRM、优化器、更新次数及随机种子保持匹配。

在一个单步错误回答上，若 p 是正确概率，L_fail=-log(1-p)。对正确性 logit z 的导数为 p，梯度下降会把该分数往下推。
实际 B 记录 row 2095 的 p=0.9791356921，对应失败损失约 3.8697、logit 梯度约 +0.9791。C 与 D 都有这一失败项，因此它支持“需要检验适配”，不支持“D 必然优于 C”。这是假定同类样本进入训练时的梯度方向分析，不是 C/D 已训练的结果，也不将该已观察案例定向塞进适配集。

多步骤时 E=sum stopgrad(w_t)*(1-p_t)，dL_fail/dz_t=stopgrad(w_t)*p_t*(1-p_t)/E。这个弱标签只说明整条回答有问题，无法保证定位到真正错误的步骤。共享模型参数还会产生跨样本影响。

D 独有的假设：避免把“终答对但过程有错”的整条解答作为成功弱监督，减少错误步骤被抬分的机会。
D 的代价：同时放弃来自真正正确的当前策略解答的有用监督；可能更容易整体压低分数或损害正确步骤。公共正负步骤锚点和原 PRM 是约束，但不是防塌缩保证。
LCA v2 App. E.3 在受控单侧噪声下仍有较稳的结果；不能由该文推断删掉成功监督必然更好。其理论也不直接保证我们使用小样本、额外锚点、删除成功项和 LoRA 后的目标有效。

二、适配不能自动解决哪一部分
1. 组内标准化的放大结构仍在。对于全部答错的组，R_i=0.2*m_i。所有 m_i 乘同一正数时，除 epsilon 的影响外，标准化优势基本不变。
   对 row 2095 所在真实八回答组做纯数值重算：原优势 +2.44009；所有过程分乘 0.1 后优势 +2.40759。分数整体降低不是 RL 学习信号改善的充分条件。
2. 步骤取 min 的规则与固定双换行切分仍在。适配有可能减少单段误判，但不提供对分段数量不敏感的保证；单段/多段均值差也不能被当作已识别的因果效应。
3. 每条回答的单个优势仍用于全部生成 token。对全错组中的相对高分回答给正优势，并不等于只奖励其中正确步骤。正优势本身不是 bug，也不能单凭终答错误就断言所有过程信号有害。
4. D 若把所有分数压到近乎无差异，可能弱化甚至消除 PRM 的影响。这不能表述为“评分器更懂数学”；必须与 A、S 和真正的过程标签诊断一起解释。

三、主四组的边界保持不变
A：仅终答奖励。
B：终答奖励 + 原始冻结 PRM。
C：终答奖励 + C 适配后的冻结 PRM。
D：终答奖励 + D 适配后的冻结 PRM。
B/C/D 全部继续采用同一 R=y+0.2*min(p)、无效输出规则、双换行切分和 group 标准化。D-C 只隔离成功弱监督系数；C-B 比较完整适配包；S 只在评分器层面拆开锚点与失败监督。
若只给 C/D 换奖励算法，D-C 在新算法下仍可比较，但 C-B 会混入适配与奖励算法两种变化，不能沿用原解释。

四、在 C/D RL 之前应该完成的检查
沿用初始策略、固定 512 道训练题各 4 条输出和 2,048 个去污染公共步骤锚点。不从 B 中挑“最能支持 D”的错误，不把验证集或 ProcessBench 加进适配。
冻结 PRM 学习率、更新次数、LoRA 配置和数据 manifest；C/D 只改 c，不根据谁赢了选择训练设置或 checkpoint。
用原定 64 道验证题各 8 条的同一份初始策略输出计算 B/S/C/D 的分数、奖励和真实优势；全错/全对/混合组及无效输出分层固定。看排序、实际优势、分数离散程度，不能只看 loss、平均分或 Pearson 相关性。
ProcessBench 保留为固定诊断：错误定位、正确链接受率、调和平均，以及终答正确子集中的有效推导 AUROC 和配对 bootstrap。不能把终答排序准确率冒充过程准确率，也不能用 ProcessBench 选超参、checkpoint 或是否保留某个实验臂。
观察到的 B 错误案例只用于事后定性检查；它们不是未见测试集。
诊断结果用于解释机制，不以“D 看起来能赢”作为启动/保留 C/D 的成功门槛；技术失败必须先修复。固定最终 24M 终点，保留 6M/12M；不挑最好节点。

五、若要检查奖励计算，最小清楚的补充实验
先不执行。可另开两个探索性副本 A_none、B_none，只把 scale_rewards 从 group 改为 none，其余配置保持一致，同一初始模型、seed 和固定生成 token 预算；不从当前 B 续跑并覆盖旧结果。
none 使用 A_i=R_i-mean(R)，能避免组内标准差把很小的过程差异标准化为量级 1，但不能纠正 PRM 的错误排序。
配对比较：
  现有 group 下的 PRM 增益 = score(B)-score(A)
  none 下的 PRM 增益 = score(B_none)-score(A_none)
这比只跑 B_none 更能区分“纯结果 RL 也受标准化影响”和“PRM 增益依赖标准化”。两个差值之差是探索性相互作用，不直接证明具体数学错误的因果机制，也不验证 D-C 在新目标下仍有效。
可预先固定 6M 作为这项补充检查的探索性终点，复用已保存的 A/B 同节点对照，共新增 12M 训练 token（PRM 与评测成本另计）；它不是原 24M 四组主结论。若日后要主张 C/D 在新奖励下的效果，需要匹配的新 C_none/D_none，不能混用旧 B。
不把关掉标准化包装为本项目的创新点，也不宣称一定会提升准确率。
